## 1. หลักการ (ทำไมต้องสะสมข้อมูลก่อน)

| ลำดับ | สิ่งที่ทำ | เวลา | ถูกลอกโดยคู่แข่ง |

  "website": "https://...",       // เว็บไซต์/IR (อ้างอิง)
  "foundedYear": 1945,            // ปีก่อตั้ง
  "ipoDate": "YYYY-MM-DD",        // วันที่เข้าตลาดจริง
  "peers": ["BBL", "SCB"],        // หุ้นกลุ่มเดียวกัน
  "sinsiNote": "หมายเหตุซินแส...", // กรณีธาตุซับซ้อน

  // ── ชั้น B: ข้อมูลตลาด (dynamic — ผ่าน API ราคา ไม่กรอกมือ!) ──
  "marketData": {                 // ★ null จนกว่าจะต่อ API (web admin ระยะ 2)

    "marketCap": 0, "avgVolume": 0, "high52w": 0, "low52w": 0,

  "primaryElement": "น้ำ",         // ธาตุหลัก (ใช้คำนวณ verdict เป็นหลัก)
  "elementReason": "การเงิน/ธนาคาร/สินเชื่อ = ธาตุน้ำ (career-business.txt); สินเชื่อบ้าน/อสังหา = ดิน (รอง)",  // ★ ทำไมถึงเป็นธาตุนี้ — ตรวจทานง่าย
  "elementSource": "career-business.txt §ธาตุน้ำ + ตรวจโดยซินแส",  // อ้างอิงแหล่งที่มา

  // ── เกรด/ขนาด (ใช้จัดลำดับ + ฉบับราคา) ──
  "tier": "SET50",                // SET50/SET100/mega/large/mid (ใช้คัด "ฉบับหุ้นไทย" vs "ทั่วโลก")
  "marketCapRank": 4,             // อันดับมาร์เก็ตแคปในตลาด (ใช้อัปเดต/เรียง)
  "isHighLiquidity": true,        // สภาพคล่องสูง? (คนไทยซื้อขายได้จริงไหม)

  // ── ตรวจทาน (review trail) ★ สำคัญที่สุด ──
  "status": "reviewed",           // draft → in_review → reviewed → published
  "reviewedBy": "ซินแส [ชื่อ]",    // ใครตรวจ
  "reviewedAt": "2026-08-04",     // วันที่ตรวจ
  "notes": "สินเชื่อบ้านทำให้มีธาตุดินปน แต่น้ำยังเป็นหลัก"  // หมายเหตุเพิ่มเติม (ไม่บังคับ)

## 3. ตารางกฎคำสำคัญ → ธาตุ (Keyword Rules)

| ธาตุ | คำสำคัญในธุรกิจ (ตัวอย่าง) |

| **ไฟ** | พลังงาน, ไฟฟ้า, โซลาร์, แบตเตอรี่, น้ำมัน, ก๊าซ, โรงพยาบาล, คลินิก, ความงาม, เครื่องสำอาง, ร้านขายยา, สื่อ/โซเชียลมีเดีย, การตลาด, อบรม/สอนพิเศษ |

## 4. ⚠️ จุดขัดแย้งในตำราต้นทาง — ต้องตัดสินใจ+จดทะเบียน (decision log)

> ต้นทาง 2 แหล่งตีความธุรกิจบางอย่างต่างกัน — **ต้องมี "คำตัดสิน" ชัดเจนต่อหัวข้อ** ไม่งั้น verdict ไม่ consistent

| ธุรกิจ | career-business.txt | Source4 §5 | คำตัดสินที่เสนอ | เหตุผล |
|---|---|---|---|---|
| การเกษตร/พืชผล | ไม้ (การเกษตร ต้นไม้) | ดิน (การเกษตร) | **ไม้** | ต้นทางหลัก (career-business) ระบุ "การเกษตร สวนดอกไม้ ต้นไม้" ไว้ใต้ไม้ |
| ขนส่ง/โลจิสติกส์ | น้ำ และ ไม้ (ทั้งคู่) | น้ำ และ ไม้ (ทั้งคู่) | **น้ำ** (โลจิสติกส์) / ไม้ (ไปรษณีย์-สื่อสาร) | ดูธุรกิจหลักของแต่ละบริษัท |
| การศึกษา/โรงเรียน | ไฟ (โรงเรียน การสอน) | ไม้ (การศึกษา) | **ไฟ** (สถาบันศึกษา) / **ไม้** (สื่อการเรียน) | แยกตามรูปแบบธุรกิจ |
| ก๊าซ/พลังงาน | แก๊ส = ไม้ (ในรายการไม้) | ไฟ (พลังงาน) | **ไฟ** | Source4 ชัดกว่า: พลังงาน=ไฟ; career-business น่าจะพิมพ์รวมผิด |
| อาหารปรุงสุก/ร้านอาหาร | น้ำ (อาหารทุกชนิด) | ไฟ (อาหารปรุงสุก) | **น้ำ** (หลัก) + ไฟ (รอง) | career-business หลัก = น้ำ; ถ้าธุรกิจเป็นร้านอาหาร/ฟาสต์ฟู้ดเด่น ให้เพิ่มไฟรอง |
| สื่อ/โซเชียล | (ไม่มีชัด) | ไฟ (โซเชียลมีเดีย) | **ไฟ** (โซเชียล/แพลตฟอร์ม) / **ไม้** (สื่อสิ่งพิมพ์) | แยก platform (ไฟ) vs print (ไม้) |

> 📌 **Decision log นี้ต้องอยู่ใน repo** (`data/decision-log.md`) — เพิ่มทุกครั้งที่เจอกรณีคลุมเครือ กันความไม่ consistent

## 5. ขั้นตอนสะสม (Workflow)

```
1. เลือกหุ้นเป้า (SET50/100 ก่อน → ตลาดโลก)
2. อ่านธุรกิจจริง: งบ 56-1 (ไทย) / 10-K (US) / รายงานประจำปี
3. เขียน business 1 บรรทัด + businessKeywords
4. map ธาตุผ่านตารางกฎ (หัวข้อ 3) → elements + primaryElement + elementReason
5. ถ้าเจอกรณีคลุมเครือ → เพิ่ม decision-log
6. ซินแสตรวจ (status: draft → in_review → reviewed)
7. ตรวจซ้ำรอบ 2 (คนละคน/อีกครั้ง) → published
8. อัปเดตเป็นรอบ (ทุก 6 เดือน ตรวจธุรกิจที่เปลี่ยน)
```

## 6. ลำดับการสะสมที่แนะนำ

| รอบ | กลุ่ม | จำนวน | ใช้ขายฉบับ |
|---|---|---|---|
| รอบ 1 | SET50 (ไทย) | ~50 | ฉบับหุ้นไทย ฿2,490 (ขายได้เลย) |
| รอบ 2 | SET100 ที่เหลือ + mai/เล็ก/กลาง | ~100 | ฉบับหุ้นไทยเต็ม |
| รอบ 3 | สหรัฐฯ (DJIA/Nasdaq 100 เด่น) | ~40 | ฉบับทั่วโลก ฿4,990 |
| รอบ 4 | จีน/ฮ่องกง + เกาหลี + ญี่ปุ่น | ~90 | ฉบับทั่วโลก |
| รอบ 5 | อินเดีย + เวียดนาม + ออส + แคนาดา | ~120 | ฉบับทั่วโลก |
| รอบ 6 | ETF/REIT/กองทุน/สินค้า/คริปโต | ~100 | ทุกฉบับ |
| รอบ 7 | **หุ้นดาวรุ่ง/ธีมอนาคต** (ต่อเนื่อง) | +50–100 | ฉบับทั่วโลก + VIP รายเดือน |

**หมายเหตุ**: รอบ 1 (SET50) สำเร็จ = ขายฉบับหุ้นไทยได้เลย ไม่ต้องรอให้ครบโลก

## 6.1 จำนวนหุ้น "น้อยไปไหม?" — เป้าหมาย 700+ รายการ

**คำตอบ: 300 ตัวน้อยไปจริง — แต่ไม่ใช่ "ยิ่งมากยิ่งดี" ต้อง "กว้าง + ลึก" ควบคู่**

### ทำไมต้องมากกว่า 300
1. **หุ้นดาวรุ่ง (rising stars)**: หุ้นเล็ก/กลางที่ยังไม่โดดเด่นวันนี้ แต่พลังในอนาคต — ลูกค้าถามแน่นอน ("แล้วตัวนี้ล่ะ?") ต้องมีคำตอบ
2. **ธีมอนาคต**: AI, EV, ชิป, BCG, การแพทย์, ความงาม, อาหารอนาคต, ดิจิทัล — ธุรกิจใหม่เกิดทุกปี
3. **IPO/เข้าใหม่**: ต้องเพิ่มได้ตลอด (ระบบ web = เพิ่มได้เรื่อยๆ)
4. **ความน่าเชื่อถือ**: ลูกค้าเช็คหุ้นที่ตัวเองถือ แล้วเจอ "ไม่มีในเล่ม" = เสียความเชื่อถือ

### แต่คุณภาพ > จำนวน (published ≠ draft)
- ทุกตัวต้องผ่าน **review 2 รอบ** ก่อน published — จำนวน draft ได้ แต่ published ต้องค่อยๆ ไล่
- **กลยุทธ์**: ฐานข้อมูลกว้าง (draft 700+) + ขายเฉพาะ published → ค่อยๆ ยกระดับ draft → published ทุกสัปดาห์ (content pipeline ต่อเนื่อง)

### ฟีเจอร์ "พลังในอนาคต" (จับคู่กับวัยจร)
> หุ้นที่ไม่เด่นวันนี้ **แต่อนาคตธาตุตรงกับวัยจรถัดไปของเจ้าชะตา** = "ดาวรุ่งประจำวัยจร"

```
ตัวอย่าง: เจ้าชะตากำลังอยู่ในวัยจรธาตุน้ำ (ลงทุนได้) → วัยจรหน้า = ธาตุทอง
  → หุ้นเทค/ชิป (ธาตุทอง) ที่วันนี้ verdict "กลาง" 
  → จะถูกแฟล็ก "🌟 ดาวรุ่ง — ธาตุตรงกับวัยจรถัดไป (อายุ X–Y)"
  → ลูกค้าเห็น "หุ้นที่ควรจับตาตั้งแต่วันนี้ เพื่อวัยจรหน้า"
```

→ ต้องการฟิลด์เพิ่มใน schema: `growthStage` (large/mid/small/startup), `theme` (AI/EV/BCG/...), `risingStar` (bool + เหตุผล), `listedDate`

## 6.2 ต้องมี "ประเภทการลงทุนอื่น" ด้วยไหม? — ต้องมี! (ไม่ใช่แค่หุ้น)

**ลูกค้าถามแน่นอน**: "แล้วกองทุนล่ะ ทองคำล่ะ คริปโตล่ะ บ้านล่ะ ฝากธนาคารล่ะ" → ถ้าเล่มมีแต่หุ้น = ตอบไม่ครบ = ขายแพงไม่ได้

| ประเภท | ตัวอย่าง | ธาตุหลัก | เหตุผล (อ้างอิง) |
|---|---|---|---|
| หุ้นรายตัว | KBANK, AAPL | ตามธุรกิจบริษัท | ระบบ verdict เดิม (หัวข้อ 2.1) |
| กองทุนรวมไทย | กองทุน SET50 Index, กองทุนทอง | ตามพอร์ต/ดัชนีอ้างอิง | คำนวณจาก sector weight |
| กองทุนต่างประเทศ | กองทุน S&P500, กองทุนอินเดีย | ตามพอร์ต | sector weight |
| ETF | SPY, MCHI, VTI | ตามดัชนี | sector weight ของดัชนี |
| REIT / Property Fund | CPNREIT, ต่างประเทศ | **ดิน** | อสังหา = ดิน (Source4 §5) |
| ตราสารหนี้/พันธบัตร | พันธบัตรรัฐบาล, หุ้นกู้ | **ดิน** (มั่นคง) | ความมั่นคง = ดิน |
| เงินฝาก/สลากออมทรัพย์ | ฝากประจำ, สลาก ธ.ก.ส. | **ดิน** (มั่นคง) / **น้ำ** (สภาพคล่อง) | ฝากประจำ=ดิน, เงินสดหมุนเวียน=น้ำ |
| ทองคำ/โลหะมีค่า | ทองแท่ง, Gold ETF, เงิน | **ทอง** | โลหะมีค่า = ทอง (career-business) |
| น้ำมัน/พลังงาน | WTI, กองทุนน้ำมัน | **ไฟ** | พลังงาน = ไฟ (Source4 §5) |
| คริปโต | BTC, ETH | **ไฟ** (ร้อนแรง/ผันผวน) + **น้ำ** (สภาพคล่อง) | ตีความตามดวง (decision log) |
| อสังหาฯ ตรง | บ้าน คอนโด ที่ดิน | **ดิน** | อสังหา = ดิน |
| Forex | USD/THB, EUR/USD | **น้ำ** | การเงิน/การแลกเปลี่ยน = น้ำ (บท 15) |
| ประกันสะสมทรัพย์/บำนาญ | ประกันบำนาญ | **ดิน** (มั่นคงระยะยาว) | การออมระยะยาว = ดิน |
| อนุพันธ์ | SET50 Futures, Options | ตามสินค้าอ้างอิง | เช่น Future อ้างอิงหุ้นน้ำ = น้ำ |

→ **Schema ต้องมี `type` field**: `"stock" | "fund" | "etf" | "reit" | "bond" | "deposit" | "commodity" | "crypto" | "real_estate" | "forex" | "insurance" | "derivative"` — verdict engine ใช้ type ประกอบการอธิบาย (เช่น กองทุน = "กระจายตามพอร์ต" / ทอง = "สินทรัพย์ปลอดภัย")

## 6.3 สรุปเป้าหมายฐานข้อมูล (v1)

| กลุ่ม | จำนวนเป้า |
|---|---|
| หุ้นไทย (SET100 + mai + เล็ก/กลาง) | ~250 |
| หุ้นโลก 8 ตลาด (30–50/ตลาด) | ~300 |
| กองทุน/ETF/REIT | ~80 |
| สินค้า/คริปโต/อสังหา/ฝาก/บอนด์/ประกัน | ~70 |

## 7. ไฟล์/ระบบในโปรเจค — **หน้าเว็บจัดการข้อมูล** (ตามที่เลือก)

> ไม่ใช่แก้ JSON มือ — แต่เป็น **หน้า Admin Web (CRUD)** สำหรับสะสม/ตรวจ/จัดการคลังข้อมูล
> แล้ว **export เป็น JSON** ให้ engine อ่าน (engine ยัง deterministic เหมือนเดิม)

```
data/
  stocks/thailand.json     // รอบ 1–2 (export จาก web)
  stocks/global.json       // รอบ 3–5 (8 ตลาด)
  stocks/commodities.json  // รอบ 6
  markets/world-map.ts     // ตารางตลาด (หัวข้อ 2.4)
  decision-log.md          // ★ บันทึกคำตัดสินกรณีคลุมเครือ

src/app/
  admin/                   // ★ หน้า Admin (เฉพาะผู้ดูแล/ซินแส)
    stocks/                //   CRUD รายการลงทุนทั้งหมด (filter: type/market/ธาตุ/status)
    markets/               //   ตาราง 8 ตลาด (ทิศ/ธาตุ)
    decisions/             //   decision log (เพิ่ม/แก้)
    review/                //   คิวตรวจ: draft → in_review → reviewed (ซินแส)
  api/
    stocks/                // GET/POST/PATCH (admin auth)
    export-stocks/         // export JSON → data/ (กดปุ่มเดียว)
```

**ทำไมเป็น web:**
1. ซินแส/ทีมกรอกได้จากทุกที่ ไม่ต้องแตะโค้ด/JSON
2. มี **คิวตรวจ (review queue)** — เห็นเลยว่าตัวไหน draft/รอตรวจ/ผ่าน
3. filter/ค้นหา: "หุ้นธาตุทอง ยังไม่ตรวจ" → ทำงานเร็วขึ้น
4. สถิติ: ความคืบหน้า (x/700 published) — เห็นเป้า
5. กัน error: form validate ฟิลด์บังคับ (primaryElement ต้องมี, elementReason ต้องมี)

**Flow ทำงาน:**
```
[Admin] เพิ่มหุ้น (เลือก type/ตลาด/กรอก business) → status=draft
  → [ซินแส] เปิดคิว review → ตรวจธาตุ+เหตุผล → in_review/reviewed
  → [Admin] กด "export JSON" → data/*.json → engine อ่าน → generate เล่ม
```

**ข้อควรตัดสินใจ (ทีหลังได้):** หน้า admin ใช้ auth แบบไหน (รหัสผ่านเดียว / LINE login / email+password) — เสนอเริ่มจากรหัสผ่าน admin ตัวเดียว ก่อน แล้วค่อยเพิ่ม role ซินแส

## 8. ชั้นธีม/บริบท (Theme & Context Layer) — ★ ข้อมูลต้องมีชีวิต

### 8.1 ทำไมต้องมี (ตอบโจทย์ "โลกเปลี่ยนทุกวัน")

> หุ้นไม่ใช่ข้อมูลนิ่ง — **หุ้นใหม่/สินค้าใหม่เข้าตลาดทุกวัน, เทรนด์เกิดใหม่ (หุ่นยนต์/AI/EV), เหตุการณ์โลกเปลี่ยนทิศ (สงคราม → หุ้นอาวุธ)**
> ถ้าคลังหุ้นมีแค่ "ธาตุคงที่" จะล้าสมัยเร็ว → ต้องมี **ชั้นธีมที่อัปเดตต่อเนื่อง** ประกบกับธาตุ

### 8.2 Schema — ธีม (Theme)

```jsonc
{
  "id": "robotics",                    // slug ภาษาอังกฤษ
  "name": "หุ่นยนต์/ระบบอัตโนมัติ",      // ชื่อไทย
  "nameEn": "Robotics and Automation",
  "category": "megatrend",             // ★ ประเภท: megatrend (ระยะยาว) / event (เหตุการณ์) / cyclical (วัฏจักร)
  "description": "หุ่นยนต์อุตสาหกรรม AI robot humanoid ระบบอัตโนมัติในโรงงาน — แนวโน้มโตระยะยาว",
  "relatedElements": ["ทอง", "ไฟ"],    // ★ ธาตุของธีมนี้ (เทียบ useful god ได้)
  "relatedSectors": ["เทค", "เครื่องจักร", "ชิป", "ยานยนต์", "พลังงาน"],
  "stocks": [                          // ★ หุ้นที่ได้อานิสงส์จากธีมนี้ (หลายตลาด)
    { "ticker": "FANUC", "market": "JP", "role": "ผู้ผลิตหุ่นยนต์หลัก" },
    { "ticker": "ABB", "market": "US", "role": "ระบบอัตโนมัติ" },
    { "ticker": "NVDA", "market": "US", "role": "ชิป AI ขับเคลื่อนหุ่นยนต์" },
    { "ticker": "TERA", "market": "TH", "role": "ผู้ผลิตชิ้นส่วน/ระบบอัตโนมัติไทย" }
  ],
  "momentum": "rising",                // ★ rising / stable / declining (อัปเดตทุกไตรมาส)
  "asOf": "2026-08-04",                // วันที่อัปเดต
  "note": "อานิสงส์จาก humanoid robot + โรงงานอัตโนมัติ"
}
```

### 8.4 ธีมตัวอย่าง (ต้องมีประจำ — อัปเดตไตรมาสละครั้ง)

| ธีม | ธาตุ | หุ้นตัวอย่าง | ประเภท |
|---|---|---|---|
| หุ่นยนต์/ระบบอัตโนมัติ (Robotics) | ทอง, ไฟ | FANUC(JP), ABB(US), NVDA(US), ไทย: ผู้ผลิตชิ้นส่วนอัตโนมัติ | megatrend |

| EV / แบตเตอรี่ | ไฟ, ทอง | TESLA, CATL(CN), ไทย: ผู้ผลิตชิ้นส่วนยานยนต์ | megatrend |
| ชิป/เซมิคอนดักเตอร์ | ทอง | TSMC, SK Hynix(KR), ASML | megatrend |
| อาหาร/ความมั่นคงอาหาร | น้ำ, ไม้ | ไทย: กลุ่มอาหาร CPF/ITC, โลก: ADM | cyclical |

### 8.5 วิธีใช้ธีมในเล่ม (เพิ่มมูลค่า)

```
บท "ธีมมาแรงประจำไตรมาส" (ใหม่ ในฉบับ ฿2,490+):
  🌟 ธีม: หุ่นยนต์/ระบบอัตโนมัติ (ธาตุทอง-ไฟ)
  → ตรงกับ useful god ของคุณ (ทอง) = ✅ ธีมนี้เข้าทางดวงคุณ
  → หุ้นที่ได้อานิสงส์: FANUC(ญี่ปุ่น), ABB, NVDA(สหรัฐฯ), ...
  → ⚠️ ธีม: อาวุธ/ป้องกันประเทศ (ธาตุทอง) = ธาตุพิฆาตดวงคุณ → ข้ามได้
```

- **verdict รวม = ธาตุหุ้น (หลัก) + ธีม (เสริม)**: หุ้นธาตุทอง + ธีม AI กำลังมา = "เหมาะมาก + แรงหนุนธีม"
- **ใครได้อานิสงส์**: เลือกธีม → ระบบลิสต์หุ้นที่เกี่ยวข้องข้ามตลาด (คำตอบ "หุ้นที่ได้อานิสงส์จาก X มีอะไรบ้าง")

### 8.6 กระบวนการอัปเดต (ข้อมูลต้องมีชีวิต — ไม่งั้นตาย)

| รอบ | อะไร | ใครทำ |
|---|---|---|
| รายสัปดาห์ | หุ้น IPO ใหม่/เข้าตลาดใหม่ → เพิ่ม draft | Admin |
| รายเดือน | เหตุการณ์โลก (สงคราม/นโยบาย/วิกฤต) → เพิ่ม/ปิด event | Admin + ซินแส |
| รายไตรมาส | ธีม momentum (rising/stable/declining) + ตรวจหุ้นในธีม | ซินแส |
| รายปี | ตรวจธาตุหุ้นที่ธุรกิจเปลี่ยน (รีแบรนด์/เปลี่ยนธุรกิจหลัก) | ซินแส |
| ทุกครั้ง | export JSON → engine ใหม่ → เล่มลูกค้าได้ข้อมูลสด | ระบบ |

**สรุป**: คลังหุ้น = ข้อมูลนิ่ง (ธาตุ/ธุรกิจ) · **ชั้นธีม = ข้อมูลมีชีวิต (เทรนด์/เหตุการณ์)** — สองชั้นประกบกัน → เล่มไม่เคยล้าสมัย และเป็นเหตุผลให้ลูกค้าต่ออายุ VIP รายเดือน (ได้ข้อมูลสดทุกเดือน)
